# Saral phase 3a implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the v1 kit: Checkbox, Radio group, Select, Tag and Card, in HTML and CSS, with core validation for the three form controls, React components, specs, portal pages and tests. Ends with v0.3.0, the portal updated, and an update sent to the consumer site's session.

**Architecture:** Native elements first, as before. Checkbox and radio are native inputs coloured with `accent-color`; select is a native `<select>`. The three form controls reuse the field's parts (`label`, `input`, `hint`, `error`) and its error rule, so core's `enhanceField` handles them all once it listens on the root instead of on one input. Tag and Card are CSS only.

**Tech Stack:** Node 24, `node:test`, Playwright, axe, TypeScript 6 for JSDoc checks. No new dependencies.

**Spec:** `docs/spec/2026-10-11-saral-v1-design.md`, sections 8, 9 and the phase 3 row of 13.

**Budget:** 5 evenings (phase 3b, the Figma library, has the other 3). Cut first if over: the interactive Card, then React `Tag` removal.

## Global Constraints

- Native elements, CSS states, `data-scope` and `data-part` on every part; tokens only; `@layer saral.components` with `:where()`; no `[hidden]`.
- Errors show by CSS: `:has([data-part="input"]:user-invalid)` with no script, `[data-invalid]` with core.
- Tag and Card ship no client JavaScript. In React only `Form` is a client component.
- No runtime dependencies. No consumer site named anywhere in the repo. Docs copy plain, no em dashes. No AI co-author trailer.

## Review Focus

1. **Moving between radios in one group.** Arrowing from one radio to the next must not check the group mid-way; only leaving the whole group does. Pinned in Task 1.
2. **A required checkbox fixed by ticking it.** Once its error shows, ticking the box clears the error at once, without leaving it. Pinned in Task 1.
3. **A required select left on its placeholder.** The placeholder option has an empty value, so the select is invalid until a real choice is made. Pinned in Task 2.
4. **A whole-card link.** Only the title is the link, its click area covers the card, and the card's other links stay clickable. Pinned in Task 2.
5. **Theme and mode.** Every new component passes axe in Mor and Kosh, light and dark, with errors showing. Pinned in Task 2.

Replace the body of `enhanceField` from the input lookup to the end with:

```js
  const inputs = /** @type {Array<HTMLInputElement | HTMLTextAreaElement | HTMLSelectElement>} */ ([
    ...root.querySelectorAll('[data-part="input"]'),
  ]);
  const input = inputs[0];
  if (!input) throw new Error('saral: a field needs a [data-part="input"]');
  let error = /** @type {HTMLElement | null} */ (root.querySelector('[data-part="error"]'));
  // A field written without an error element gets one, so it can still say
  // what is wrong.
  if (!error) {
    error = document.createElement('p');
    error.setAttribute('data-scope', root.getAttribute('data-scope') ?? 'field');
    error.setAttribute('data-part', 'error');
    root.append(error);
  }
  const message = error;
  if (!message.id) message.id = `${input.id || `saral-field-${++count}`}-error`;
  let edited = false;
  let shown = false;

  /** @param {boolean} add */
  const describe = (add) => {
    for (const el of inputs) {
      const ids = new Set((el.getAttribute('aria-describedby') ?? '').split(/\s+/).filter(Boolean));
      if (add) ids.add(message.id);
      else ids.delete(message.id);
      if (ids.size) el.setAttribute('aria-describedby', [...ids].join(' '));
      else el.removeAttribute('aria-describedby');
    }
  };
  const show = () => {
    message.textContent = messageFor(input, message);
    for (const el of inputs) el.setAttribute('aria-invalid', 'true');
    root.setAttribute('data-invalid', '');
    describe(true);
    shown = true;
  };
  const hide = () => {
    for (const el of inputs) el.removeAttribute('aria-invalid');
    root.removeAttribute('data-invalid');
    describe(false);
    shown = false;
  };
  // A radio group is valid or invalid as a whole, so its first input speaks
  // for all of them.
  const validate = () => {
    if (input.validity.valid) {
      hide();
      return true;
    }
    show();
    return false;
  };
  const onChange = () => {
    edited = true;
    if (shown) validate();
  };
  // Check when focus leaves the whole field, so moving between the radios of
  // one group does not check it half way.
  /** @param {FocusEvent} e */
  const onFocusOut = (e) => {
    if (edited && !(e.relatedTarget instanceof Node && root.contains(e.relatedTarget))) validate();
  };
  /** @param {Event} e */
  const onInvalid = (e) => {
    e.preventDefault();
    show();
  };
  root.addEventListener('input', onChange);
  root.addEventListener('change', onChange);
  root.addEventListener('focusout', onFocusOut);
  root.addEventListener('invalid', onInvalid, true);
  return {
    validate,
    destroy() {
      root.removeEventListener('input', onChange);
      root.removeEventListener('change', onChange);
      root.removeEventListener('focusout', onFocusOut);
      root.removeEventListener('invalid', onInvalid, true);
    },
  };
}
```

// Shared pieces for the React components that follow the field contract.

/**
 * @typedef {{ valueMissing?: string, typeMismatch?: string, tooLong?: string, tooShort?: string, patternMismatch?: string }} FieldMessages
 */

/** @type {Record<keyof FieldMessages, string>} */
const DATA = {
  valueMissing: 'data-message-value-missing',
  typeMismatch: 'data-message-type-mismatch',
  tooLong: 'data-message-too-long',
  tooShort: 'data-message-too-short',
  patternMismatch: 'data-message-pattern-mismatch',
};

/**
 * @param {string} scope
 * @returns {(name: string) => { 'data-scope': string, 'data-part': string }}
 */
export const parts = (scope) => (name) => ({ 'data-scope': scope, 'data-part': name });

/** @param {FieldMessages} messages */
export const messageData = (messages) =>
  Object.fromEntries(Object.entries(messages).map(([k, v]) => [DATA[/** @type {keyof FieldMessages} */ (k)], v]));

/**
 * The error's own text is what people see with no script, so it is the most
 * useful general message.
 * @param {FieldMessages} messages
 */
export const defaultMessage = (messages) => messages.typeMismatch ?? messages.valueMissing ?? '';

/** @param {string} raw from useId() */
export const safeId = (raw) => `saral-${raw.replace(/[^A-Za-z0-9_-]/g, '')}`;

/**
 * @typedef {Omit<import('react').InputHTMLAttributes<HTMLInputElement>, 'children' | 'type'> & {
 *   label: string, hint?: string, messages?: import('./parts.mjs').FieldMessages,
 * }} CheckboxProps
 */

const part = parts('checkbox');

/** @param {CheckboxProps} props */
export function Checkbox({ label, hint, messages = {}, id, ...input }) {

  const hintId = hint ? `${inputId}-hint` : undefined;
  return h(

    part('root'),
    h('input', { ...input, type: 'checkbox', ...part('input'), id: inputId, 'aria-describedby': hintId }),
    h('label', { ...part('label'), htmlFor: inputId }, label),
    hint ? h('p', { ...part('hint'), id: hintId }, hint) : null,

import { createElement as h, useId } from 'react';
import { parts, messageData, defaultMessage, safeId } from './parts.mjs';

/**
 * @typedef {{
 *   legend: string, name: string, options: Array<{ value: string, label: string }>,
 *   hint?: string, messages?: import('./parts.mjs').FieldMessages, required?: boolean, defaultValue?: string,
 * }} RadioGroupProps
 */

const part = parts('radio');

/**
 * The first radio carries `required`, which makes the whole group required.
 * @param {RadioGroupProps} props
 */
export function RadioGroup({ legend, name, options, hint, messages = {}, required = false, defaultValue }) {
  const base = safeId(useId());
  const hintId = hint ? `${base}-hint` : undefined;
  return h(
    'fieldset',
    part('root'),
    h('legend', part('label'), legend),
    ...options.map((o, i) =>
      h(
        'div',
        { ...part('item'), key: o.value },
        h('input', {
          ...part('input'),
          type: 'radio',
          id: `${base}-${i}`,
          name,
          value: o.value,
          defaultChecked: o.value === defaultValue ? true : undefined,
          required: required && i === 0 ? true : undefined,
          'aria-describedby': hintId,
        }),
        h('label', { ...part('item-label'), htmlFor: `${base}-${i}` }, o.label),
      ),
    ),
    hint ? h('p', { ...part('hint'), id: hintId }, hint) : null,
    h('p', { ...part('error'), id: `${base}-error`, ...messageData(messages) }, defaultMessage(messages)),
  );
}

```markdown
# 0003: Native form controls

Status: adopted, 2026-10-12

## Decision

- Checkbox and radio are native inputs, coloured with `accent-color` and sized to the 24 by 24 pixel minimum target. Select is a native `<select>` with the field's frame and an arrow drawn in `currentColor`.
- All three follow the field contract (`label`, `input`, `hint`, `error`), so one core handler validates every field-like control. It listens on the field's root, so a radio group is checked as a whole, and only when focus leaves the group.
- Tag and Card ship no script. A removable tag's button does whatever the page decides.

## Why

Native controls bring keyboard handling, screen-reader names and form participation from the browser, on every device. A custom checkbox or listbox has to rebuild all of that and tends to get it wrong. The research behind Saral found custom selects and comboboxes to be where funded libraries still lag.
```
