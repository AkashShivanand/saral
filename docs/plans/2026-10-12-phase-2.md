# Saral phase 2 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The contact-form slice: Field (with its error and hint), Notice, Button and Link, as plain HTML plus Saral component CSS, a small optional script for better error messages, and a thin React adapter. Works with JavaScript off. Ends with tag v0.2.0, then a try-out on the first consumer site.

**Architecture:** Markup is the contract (`data-scope`, `data-part`, native elements). `packages/css/src/*.css` styles it with tokens only, compiled into `dist/css/components.css` by the existing build. `packages/core/src/` adds behaviour HTML lacks: when a field shows its error, what it says, focus on the first error, a pending submit button. `packages/react/src/` renders the same markup; only `Form` is a client component. Core and React are JavaScript with JSDoc types, checked by TypeScript, with `.d.ts` files generated into `dist/types/` so TypeScript consumers get closed unions.

**Tech Stack:** Node 24, `node:test`. Dev dependencies, first ones in the repo: typescript 6.0.3, react 19.3.0, react-dom 19.3.0, @types/react 19.3.0, @playwright/test 1.64.0, @axe-core/playwright 4.13.0. React is an optional peer dependency.

**Spec:** `docs/spec/2026-10-11-saral-v1-design.md`, sections 6.2, 8, 9, 11 and the phase 2 row of section 13.

**Budget:** 5 evenings. Cut first if over: the React `render` prop, then the CSS lint test.

## Global Constraints

- A contact form built with Saral must keep working with JavaScript off. Core is an enhancement, never a requirement.
- Interaction states come from CSS (`:hover` inside `@media (hover: hover)`, `:active`, `:focus-visible`, `:disabled`, `:user-invalid`). Code sets only `data-invalid` and `data-pending`.
- Every part carries `data-scope` and `data-part`. Component CSS lives in `@layer saral.components`, every selector inside `:where()`, ordered base, variants, hover, active, focus, disabled.
- Component CSS uses tokens for every colour; a test fails on any raw colour or unknown `--saral-*` variable.
- Button, Link, Notice and Field ship no client JavaScript in React. Only `Form` is `'use client'`.
- No private names. Docs copy plain, no em dashes. No AI co-author trailer.

## Review Focus

1. **Back button after submit.** A browser restoring the page from its back-forward cache must not leave the button stuck pending. Pinned in Task 2.
2. **Hint plus error.** A field with a hint must keep the hint in `aria-describedby` when the error is added and after it is removed. Pinned in Task 2.
3. **Double submit.** A second press while pending must not post twice. Pinned in Task 2.
4. **System dark with the theme on `<html>`.** A page that sets `data-saral-theme` on `<html>` must still follow the system mode. Pinned in Task 1.
5. **React Strict Mode.** Effects run twice in development; `Form` must not attach listeners twice. Pinned in Task 3.

```js
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';
import { ROOT } from '../../tokens/src/build.mjs';
import mor from '../../../dist/js/mor.mjs';

const dir = join(ROOT, 'packages/css/src');
const files = readdirSync(dir).filter((f) => f.endsWith('.css'));
const read = (f) => readFileSync(join(dir, f), 'utf8').replace(/\/\*[\s\S]*?\*\//g, '');
const known = new Set(Object.keys(mor.light).map((p) => `--saral-${p.replaceAll('.', '-')}`));

test('there is component CSS to check', () => {
  assert.deepEqual(files.sort(), ['button.css', 'field.css', 'link.css', 'notice.css']);
});

test('component CSS uses no raw colours', () => {
  const raw = /#[0-9a-f]{3,8}\b|\b(?:rgba?|hsla?|hwb|lab|lch|oklab|oklch|color)\(|\b(?:white|black|red|green|blue|gray|grey|orange|yellow|purple|pink)\b/i;
  for (const f of files) assert.equal(read(f).match(raw), null, f);
});

test('every --saral variable used exists in the tokens', () => {
  for (const f of files) {
    for (const [, name] of read(f).matchAll(/var\((--saral-[\w-]+)/g)) assert.ok(known.has(name), `${f}: ${name}`);
  }
});

test('every rule is in the components layer and wrapped in :where()', () => {
  for (const f of files) {
    const css = read(f);
    assert.ok(css.trimStart().startsWith('@layer saral.components {'), f);
    for (const line of css.split('\n')) {
      const t = line.trim();
      if (t.endsWith('{') && !t.startsWith('@')) assert.ok(t.startsWith(':where('), `${f}: ${t}`);
    }
  }
});
```

`packages/core/src/field.mjs`:

```js
// Field behaviour HTML does not give: when the error shows, what it says, and
// wiring it to the input for screen readers. Without this script the field
// still works: the browser validates on submit and :user-invalid marks the
// border. Timing: check when the person leaves a field they typed in; once
// an error shows, re-check as they type; never interrupt mid-typing.

/** @typedef {{ validate(): boolean, destroy(): void }} FieldHandle */

/** @type {ReadonlyArray<[keyof ValidityState, string]>} */
const MESSAGES = [
  ['valueMissing', 'messageValueMissing'],
  ['typeMismatch', 'messageTypeMismatch'],
  ['patternMismatch', 'messagePatternMismatch'],
  ['tooLong', 'messageTooLong'],
  ['tooShort', 'messageTooShort'],
];

let count = 0;

/**
 * @param {HTMLInputElement | HTMLTextAreaElement} input
 * @param {HTMLElement} error
 */
function messageFor(input, error) {
  for (const [state, key] of MESSAGES) {
    if (input.validity[state]) return error.dataset[key] ?? input.validationMessage;
  }
  return input.validationMessage;
}

/**
 * @param {HTMLElement} root the element with data-scope="field" data-part="root"
 * @returns {FieldHandle}
 */
export function enhanceField(root) {
  const input = /** @type {HTMLInputElement | HTMLTextAreaElement | null} */ (root.querySelector('[data-part="input"]'));
  const error = /** @type {HTMLElement | null} */ (root.querySelector('[data-part="error"]'));
  if (!input || !error) throw new Error('saral: a field needs [data-part="input"] and [data-part="error"]');
  if (!error.id) error.id = `${input.id || `saral-field-${++count}`}-error`;
  let edited = false;
  let shown = false;

  /** @param {boolean} add */
  const describe = (add) => {
    const ids = new Set((input.getAttribute('aria-describedby') ?? '').split(/\s+/).filter(Boolean));
    if (add) ids.add(error.id);
    else ids.delete(error.id);
    if (ids.size) input.setAttribute('aria-describedby', [...ids].join(' '));
    else input.removeAttribute('aria-describedby');
  };
  const show = () => {
    error.textContent = messageFor(input, error);
    error.hidden = false;
    input.setAttribute('aria-invalid', 'true');
    root.setAttribute('data-invalid', '');
    describe(true);
    shown = true;
  };
  const hide = () => {
    error.hidden = true;
    input.removeAttribute('aria-invalid');
    root.removeAttribute('data-invalid');
    describe(false);
    shown = false;
  };
  const validate = () => {
    if (input.validity.valid) {
      hide();
      return true;
    }
    show();
    return false;
  };
  const onInput = () => {
    edited = true;
    if (shown) validate();
  };
  const onBlur = () => {
    if (edited) validate();
  };
  /** @param {Event} e */
  const onInvalid = (e) => {
    e.preventDefault();
    show();
  };
  input.addEventListener('input', onInput);
  input.addEventListener('blur', onBlur);
  input.addEventListener('invalid', onInvalid);
  return {
    validate,
    destroy() {
      input.removeEventListener('input', onInput);
      input.removeEventListener('blur', onBlur);
      input.removeEventListener('invalid', onInvalid);
    },
  };
}
```

`packages/core/src/form.mjs`:

```js
// Takes validation over from the browser so errors show inline, in the page's
// own words, and focus moves to the first one. Submitting stays a normal form
// post. If this script never runs, the browser's own validation still works.
import { enhanceField } from './field.mjs';
import { setPending } from './pending.mjs';

/**
 * @param {HTMLFormElement} form
 * @returns {{ destroy(): void }}
 */
export function enhanceForm(form) {
  const fields = [...form.querySelectorAll('[data-scope="field"][data-part="root"]')].map((r) =>
    enhanceField(/** @type {HTMLElement} */ (r)),
  );
  form.noValidate = true;
  /** @type {HTMLElement | null} */
  let pending = null;

  /** @param {SubmitEvent} e */
  const onSubmit = (e) => {
    if (pending) {
      e.preventDefault();
      return;
    }
    if (!form.checkValidity()) {
      e.preventDefault();
      /** @type {HTMLElement | null} */ (form.querySelector('[aria-invalid="true"]'))?.focus();
      return;
    }
    pending = /** @type {HTMLElement | null} */ (e.submitter ?? form.querySelector('[type="submit"]'));
    if (pending) setPending(pending, true);
  };
  /** @param {PageTransitionEvent} e */
  const onShow = (e) => {
    if (e.persisted && pending) {
      setPending(pending, false);
      pending = null;
    }
  };
  form.addEventListener('submit', onSubmit);
  window.addEventListener('pageshow', onShow);
  return {
    destroy() {
      form.removeEventListener('submit', onSubmit);
      window.removeEventListener('pageshow', onShow);
      form.noValidate = false;
      for (const f of fields) f.destroy();
    },
  };
}
```

```js
import { createElement as h, useId } from 'react';

/**
 * @typedef {{ valueMissing?: string, typeMismatch?: string, tooLong?: string, tooShort?: string, patternMismatch?: string }} FieldMessages
 * @typedef {Omit<import('react').InputHTMLAttributes<HTMLInputElement>, 'children'> & {
 *   label: string,
 *   hint?: string,
 *   messages?: FieldMessages,
 *   multiline?: boolean,
 *   rows?: number,
 * }} FieldProps
 */

/** @type {Record<keyof FieldMessages, string>} */
const DATA = {
  valueMissing: 'data-message-value-missing',
  typeMismatch: 'data-message-type-mismatch',
  tooLong: 'data-message-too-long',
  tooShort: 'data-message-too-short',
  patternMismatch: 'data-message-pattern-mismatch',
};

/** @param {string} part */
const part = (part) => ({ 'data-scope': 'field', 'data-part': part });

/**
 * Markup only, so it renders on the server with no client JavaScript. Put it
 * inside <Form> to get inline errors; on its own the browser validates it.
 * @param {FieldProps} props
 */
export function Field({ label, hint, messages = {}, multiline = false, id, ...input }) {
  const auto = useId().replace(/[^A-Za-z0-9_-]/g, '');
  const inputId = id ?? `saral-${auto}`;
  const hintId = hint ? `${inputId}-hint` : undefined;
  const data = Object.fromEntries(
    Object.entries(messages).map(([k, v]) => [DATA[/** @type {keyof FieldMessages} */ (k)], v]),
  );
  return h(
    'div',
    part('root'),
    h('label', { ...part('label'), htmlFor: inputId }, label),
    h(multiline ? 'textarea' : 'input', { ...input, ...part('input'), id: inputId, 'aria-describedby': hintId }),
    hint ? h('p', { ...part('hint'), id: hintId }, hint) : null,
    h('p', { ...part('error'), id: `${inputId}-error`, hidden: true, ...data }, messages.valueMissing ?? ''),
  );
}
```

```markdown
# 0002: Components, core and the React adapter

Status: adopted, 2026-10-12

## Decision

- A component is markup plus CSS. The markup is native elements with `data-scope` and `data-part`. The CSS uses tokens only and lives in `@layer saral.components`.
- Interaction states come from CSS. Script sets only `data-invalid` and `data-pending`.
- Core is optional. A form built with Saral posts, validates and shows invalid fields with JavaScript off. Core adds inline errors in the page's own words, focus on the first error, and a pending submit button.
- Core and the React adapter are JavaScript with JSDoc types, checked by TypeScript 6, with `.d.ts` files generated into `dist/types`. This keeps the code runnable with no build step, which matters because sites install Saral from a git tag.
- In React, only `Form` is a client component. `Field`, `Button`, `Link` and `Notice` render on the server and ship no JavaScript.
- Errors are linked with `aria-describedby` and read when the field is focused, not announced through a live region, so each is heard once.

## Why

A contact form should work on a dead script bundle, an old browser or a cheap phone. Saral's first components had to keep that true.
```
