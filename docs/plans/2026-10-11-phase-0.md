# Saral phase 0 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Saral repo its foundations: a confidentiality guard that blocks private names, the README, the MIT licence, the version rules and the agent guide.

**Architecture:** Zero-dependency Node ESM. The guard is one module (`tools/guard/guard.mjs`) with pure functions plus a CLI, wired into git hooks through `core.hooksPath` and into a GitHub Actions workflow. It holds no terms; it reads them from outside the repo. Everything else in this phase is documentation.

**Tech Stack:** Node 24 (floor 20), `node:test`, git hooks, GitHub Actions.

**Spec:** `docs/spec/2026-10-11-saral-v1-design.md` (sections 1, 6.4, 10, 12, 13).

**Budget:** one evening. If it runs out, nothing in this phase is cut; finish it the next evening.

## Global Constraints

- No runtime or dev dependencies in phase 0. Node built-ins only.
- ES modules, `.mjs` files. No TypeScript in phase 0.
- The repo is public. No private name may appear in any file, path or commit message, **including this plan and the guard's tests**. Tests use made-up terms only (`zebracorp`, `blue heron`).
- The guard never prints a term. CI logs on a public repo are public.
- Copy in every Markdown file: plain words, sentence case headings, no em dashes, no hype.
- Commit messages carry no AI co-author trailer.
- Every change is logged in `CHANGELOG.md`, dated, newest first.
- Do not push to GitHub in phase 0. The first push happens at v0.1 (end of phase 1).
- Licence: MIT, `Copyright (c) 2026 Akash Kumar`.

## Review Focus

1. **A term leaking through guard output.** CI logs are public, so a hit must name the place and the term's number, never the term, and a file path that contains a term must be printed masked (`***`). Pinned in Task 2.
2. **No term list.** A new machine, or a pull request from a fork that cannot read the CI secret, must fail with exit 2, never pass as clean. Pinned in Tasks 1 and 2.
3. **Terms written with separators or in another case.** `ZebraCorp`, `zebracorp_portal`, `(zebracorp)`, `blue-heron`, and `Blue` and `Heron` split across a line break in a commit message must all be caught, while `zebracorpx` must not. Pinned in Task 1.
4. **Names inside binary files.** A PNG or PDF can carry plain-text metadata. Binary content is scanned as Latin-1, not skipped. Pinned in Task 2.
5. **Bypassing the hook.** `git commit --no-verify` skips local hooks, so CI rescans the whole tree and every commit message (`--all`, `--log HEAD`). Git's own `#` comment lines in a commit message template must not trigger a hit. Pinned in Task 2 and wired in Task 3.

`tools/guard/guard.mjs`:

```js
#!/usr/bin/env node
// Saral confidentiality guard.
// It holds no terms. It reads them from SARAL_GUARD_TERMS (the CI secret) or
// from a file outside the repo. It never prints a term: output names the place
// and the term's number in the private list, because CI logs are public.
import { readFileSync, existsSync } from 'node:fs';
import { homedir } from 'node:os';
import { join } from 'node:path';

export const DEFAULT_TERMS_FILE = join(homedir(), '.config', 'saral', 'private-terms.txt');

export function parseTerms(raw) {
  return raw
    .split(/\r?\n/)
    .map((t) => t.trim())
    .filter((t) => t && !t.startsWith('#'));
}

export function loadTerms(env = process.env) {
  if (env.SARAL_GUARD_TERMS) return parseTerms(env.SARAL_GUARD_TERMS);
  const file = env.SARAL_GUARD_TERMS_FILE || DEFAULT_TERMS_FILE;
  return existsSync(file) ? parseTerms(readFileSync(file, 'utf8')) : [];
}

const escape = (s) => s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');

// A term matches when it is not part of a longer word: a letter or digit on
// either side blocks the match; spaces, punctuation, _ and - do not. Words of
// a multi-word term may be split by whitespace (line breaks too), _ or -.
export function compile(terms) {
  return terms.map((t) => {
    const body = t.split(/\s+/).map(escape).join('[\\s_-]+');
    return new RegExp(`(?<![\\p{L}\\p{N}])${body}(?![\\p{L}\\p{N}])`, 'giu');
  });
}

export function scanText(text, patterns, where) {
  const hits = [];
  patterns.forEach((re, i) => {
    for (const m of text.matchAll(re)) {
      hits.push({ where, line: text.slice(0, m.index).split('\n').length, term: i + 1 });
    }
  });
  return hits;
}

export function mask(text, patterns) {
  return patterns.reduce((t, re) => t.replace(re, '***'), text);
}
```

import assert from 'node:assert/strict';
import { spawnSync, execFileSync } from 'node:child_process';
import { mkdtempSync, writeFileSync, mkdirSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { join, dirname } from 'node:path';
import { fileURLToPath } from 'node:url';

const GUARD = join(dirname(fileURLToPath(import.meta.url)), 'guard.mjs');

function repo() {
  const dir = mkdtempSync(join(tmpdir(), 'saral-guard-'));
  const git = (...args) =>
    execFileSync('git', ['-c', 'user.name=t', '-c', 'user.email=t@t', '-c', 'commit.gpgsign=false', ...args], { cwd: dir });
  git('init', '-q');
  const terms = join(dir, '..', `${dir.split('/').pop()}-terms.txt`);
  writeFileSync(terms, '# test list\nzebracorp\nblue heron\n');
  const guard = (args, env = {}) => {
    const r = spawnSync('node', [GUARD, ...args], {
      cwd: dir,
      encoding: 'utf8',
      env: { PATH: process.env.PATH, HOME: dir, SARAL_GUARD_TERMS_FILE: terms, ...env },
    });
    return { code: r.status, out: r.stdout + r.stderr };
  };
  const write = (path, content) => {
    mkdirSync(dirname(join(dir, path)), { recursive: true });
    writeFileSync(join(dir, path), content);
  };
  return { dir, git, guard, write, terms };
}

const leaks = (out) => /zebracorp|blue[\s_-]*heron/i.test(out);

test('staged clean file passes', () => {
  const r = repo();
  r.write('a.md', 'nothing private here\n');
  r.git('add', 'a.md');
  assert.deepEqual(r.guard(['--staged']).code, 0);
});

test('staged file containing a term fails without printing the term', () => {
  const r = repo();

  r.git('add', 'a.md');

  assert.equal(res.code, 1);
  assert.match(res.out, /guard: a\.md:2 matches private term #1/);

test('a term in a file path fails and the path is printed masked', () => {

  assert.match(res.out, /docs\/\*\*\*-notes\.md/);
  assert.equal(leaks(res.out), false);

test('a term inside a binary file is caught', () => {
  const r = repo();
  r.write('img.png', Buffer.concat([Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x00, 0x00]), Buffer.from('Author: zebracorp'), Buffer.from([0x00])]));
  r.git('add', 'img.png');
  assert.equal(r.guard(['--staged']).code, 1);
});

test('no term file fails with exit 2', () => {
  const r = repo();
  assert.equal(r.guard(['--staged'], { SARAL_GUARD_TERMS_FILE: join(r.dir, 'missing.txt') }).code, 2);

test('a term file with only comments fails with exit 2', () => {
  const r = repo();
  r.write('only-comments.txt', '# nothing\n\n');
  assert.equal(r.guard(['--staged'], { SARAL_GUARD_TERMS_FILE: join(r.dir, 'only-comments.txt') }).code, 2);

  const r = repo();

  r.git('commit', '-q', '--allow-empty', '-m', 'third');

  assert.equal(res.code, 1);
  assert.match(res.out, /commit [0-9a-f]{7} message/);
  assert.equal(leaks(res.out), false);
});

test('--all scans every tracked file', () => {
  const r = repo();
  r.write('a.md', 'clean\n');
  r.write('b.md', 'the blue-heron project\n');
  r.git('add', '.');
  r.git('commit', '-q', '-m', 'x');
  assert.equal(r.guard(['--all']).code, 1);
});

test('unknown mode exits 2', () => {
  assert.equal(repo().guard(['--nope']).code, 2);
});

```js
const git = (args) => execFileSync('git', args, { maxBuffer: 1 << 28 });

const listZ = (args) => git(args).toString('utf8').split('\0').filter(Boolean);

// Binary files are scanned as Latin-1, not skipped: images and PDFs can carry
// plain-text metadata.
const decode = (buf) => buf.toString(buf.includes(0) ? 'latin1' : 'utf8');

function scanFile(path, buf, patterns) {
  const where = mask(path, patterns);
  return [
    ...scanText(path, patterns, `${where} (path)`).map((h) => ({ ...h, line: 0 })),
    ...scanText(decode(buf), patterns, where),
  ];
}

export function run(argv, env = process.env) {
  const terms = loadTerms(env);
  if (terms.length === 0) {
    const file = env.SARAL_GUARD_TERMS_FILE || DEFAULT_TERMS_FILE;
    console.error(`guard: no private term list. Set SARAL_GUARD_TERMS or create ${file}, one term per line.`);
    return 2;
  }
  const patterns = compile(terms);
  const [mode, arg] = argv;
  const hits = [];

  if (mode === '--staged') {
    for (const path of listZ(['diff', '--cached', '--name-only', '--diff-filter=ACMR', '-z'])) {
      hits.push(...scanFile(path, git(['show', `:${path}`]), patterns));
    }
  } else if (mode === '--all') {
    for (const path of listZ(['ls-files', '-z'])) {
      if (existsSync(path)) hits.push(...scanFile(path, readFileSync(path), patterns));
    }
  } else if (mode === '--message' && arg) {
    const text = readFileSync(arg, 'utf8')
      .split('\n')
      .filter((l) => !l.startsWith('#'))
      .join('\n');
    hits.push(...scanText(text, patterns, 'commit message'));
  } else if (mode === '--log' && arg) {
    const out = git(['log', '--format=%H%x01%B%x00', arg]).toString('utf8');
    for (const entry of out.split('\0')) {
      const [sha, body] = entry.replace(/^\n/, '').split('\x01');
      if (sha && body !== undefined) {
        hits.push(...scanText(body, patterns, `commit ${sha.slice(0, 7)} message`));
      }
    }
  } else {
    console.error('usage: guard.mjs --staged | --all | --message <file> | --log <rev-range>');
    return 2;
  }

  for (const h of hits) console.error(`guard: ${h.where}:${h.line} matches private term #${h.term}`);
  if (hits.length) {
    console.error('guard: blocked. Remove the private name and try again. Do not use --no-verify.');
    return 1;
  }
  console.log('guard: clean');
  return 0;
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  process.exit(run(process.argv.slice(2)));
}
```

````markdown
# Saral

Saral means simple. It is a design system where the look is a theme you can swap, and every part is plain, accessible HTML.

**Status: in design.** Nothing is built yet and there is nothing to install. The spec, the research behind it and the build log are all in this repo. Progress is logged in the [changelog](CHANGELOG.md).

## What using it will look like

```html
<link rel="stylesheet" href="saral/themes/mor.css">

<div data-scope="field" data-part="root">
  <label data-part="label" for="email">Email</label>
  <input data-part="input" id="email" name="email" type="email" required>
  <p data-part="error" id="email-error" hidden>Enter an email address like name@example.com</p>
</div>
```

Swap the theme file and the same markup takes another look:

- **Mor**, Saral's default: peacock teal, square corners.
- **Ember**: the theme [akashshivanand.com](https://akashshivanand.com) uses.
- **Kosh**: a made-up savings app. Dark, turmeric yellow, round corners.

Remove the theme and the field still works, unstyled.

## How it is built

- Design tokens in the W3C design token format, compiled to CSS, JavaScript and Tailwind, and later to Figma, Swift and Compose.
- Components on native HTML elements. Hover, focus and pressed states come from CSS, so simple components ship no JavaScript.
- Behaviour HTML does not give, like when a field shows its error, lives in a small TypeScript core with no styles.
- Every rule a machine can check is checked in CI.

# Versions

## Before 1.0

Saral stays on 0.x until the component kit is complete. In 0.x, any release may break things. Every break is written in the changelog.

## From 1.0

| Change | Version bump |
|---|---|
| Add a token, part, prop, component or attribute | minor |
| Change a token value as a declared design change | minor |
| Fix a wrong token value | patch |
| Rename or remove a token, `data-scope`, `data-part` or state attribute | major |
| Change an ARIA role, or add or remove a landmark | major |
| Deprecate anything | minor, with `@deprecated` and a lint rule |
| Remove anything deprecated | major |

## Stability labels

- **preview**: outside the promise above. Everything new starts here.
- **stable**: covered by the table.
- **deprecated**: still works, flagged by lint, removed only in a major.

In v1, the Figma, Swift and Compose outputs and the Kosh theme stay preview.

# Saral: guide for agents

Short on purpose. Read it before changing anything.

## State

Phase 0. No tokens, components or packages exist yet. Do not import, document or invent any. A component exists only if its spec is in `specs/`.

## Rules

1. Never write a private name into this repo: not in a file, a path or a commit message. The guard (`tools/guard/`) blocks it. Never bypass it with `--no-verify`, and never print the term list.
2. Components use semantic tokens only. No raw colours, sizes or durations.
3. Native elements first. Interaction states come from CSS: `:hover` inside `@media (hover: hover)`, `:active`, `:focus-visible`, `:disabled`, `:checked`, `:user-invalid`. Only two state attributes are set by code: `data-invalid` and `data-pending`.
4. Every part carries `data-scope` and `data-part`.
5. Button, Link, Card, Tag and Notice ship no client JavaScript.
6. Docs copy: plain words, sentence case, no em dashes, no hype.
7. Log every change in `CHANGELOG.md`, dated, newest first. Write a decision record in `docs/decisions/` when a decision is first used.
8. Versions follow `docs/versioning.md`.

## Wrong and right

```html
<!-- wrong: a div pretending to be a button -->
<div class="btn" onclick="send()">Send</div>
<!-- right -->
<button data-scope="button" data-part="root" type="submit">Send</button>
```

```css
/* wrong: hover set by JavaScript, or sticky on touch screens */
[data-scope="button"].is-hovered { }
/* right */
@media (hover: hover) { [data-scope="button"]:hover { } }
```

## Map

- `docs/spec/`: the v1 contract
- `docs/research/`: the evidence behind it
- `docs/versioning.md`: what counts as a breaking change
- `tools/guard/`: the confidentiality guard

## Commands

- `npm run setup`: once per clone, turns on the git hooks
- `npm test`: all tests
- `npm run guard`: scan every file and every commit message
````
